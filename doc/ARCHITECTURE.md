# XAPI 项目架构设计文档

## 1. 概述
XAPI 是一个基于 Docker 容器化部署的商业级 API 中转与分发平台。它采用 OpenAI 协议标准，为下游应用提供统一的模型调用接口、额度管理与负载均衡服务。该架构设计充分考虑了 Windows 开发环境与 Linux 生产环境的无损迁移能力。

## 2. 核心架构拓扑
本系统采用经典的高可用容器化架构，由三个核心服务组成：

### 2.1 服务组件
- **New API (API Gateway)**: 核心业务层，提供 Web 管理控制台与 OpenAI 协议 API 网关。
- **MySQL 8.0**: 关系型数据库，用于持久化存储用户信息、令牌 (Tokens)、渠道 (Channels) 配置及调用日志。
- **Redis Alpine**: 高性能键值存储，用于缓存会话状态、限流数据 (Rate Limiting) 及 Token 校验，以提升网关吞吐量。

## 3. 部署方案
采用 Docker Compose 进行单机编排，确保环境一致性。

### 3.1 目录结构
```text
D:\traeWorkspace\XAPI\
├── docker-compose.yml    # 容器编排定义
├── data/                 # New API 运行时数据
├── logs/                 # 系统运行日志
├── images/               # 静态资源（如 Logo）
├── mysql/data/           # MySQL 持久化数据
└── redis/data/           # Redis 持久化数据
```

### 3.2 环境变量设计
- **安全性**: 采用标准化密码管理，通过环境变量注入 MySQL 与 Redis 的访问凭证。
- **灵活性**: 支持通过环境变量调整 `GLOBAL_API_RATE_LIMIT` 等限流阈值，以应对不同负载场景。

## 4. 业务数据流
1. **请求接入**: 客户端发起 HTTP/HTTPS 请求至 New API 网关。
2. **鉴权与校验**: 网关通过 Redis 验证令牌有效性，并从 MySQL 读取用户额度与分组配置。
3. **路由分发**: 网关根据请求模型匹配最优配置的渠道 (Channel)。
4. **上游转发**: 网关向目标 AI 提供商（如 DeepSeek、OpenAI）转发请求。
5. **记录与结算**: 响应返回后，异步更新调用日志及用户余额。

## 5. 迁移与维护标准
- **跨平台一致性**: 所有路径挂载采用相对路径 (`./path`)，避免绝对路径硬编码。
- **配置文件编码**: 系统配置文件采用 UTF-8 编码，统一使用 Linux 风格换行符 (LF)。
- **数据导出规范**: 支持通过标准 `mysqldump` 工具导出 SQL 备份文件，确保可平滑导入至 Linux 物理服务器。

## 6. 安全规范
- 建议定期备份 `mysql/data` 数据卷。
- 严禁将 API Token 与敏感配置直接提交至公开代码仓库 (已通过 `.gitignore` 忽略运行时目录)。
- 后续建议在生产环境通过 Nginx 进行反向代理并启用 HTTPS 加密。
